# Тестовое задание. Сопоставление деклараций и регуляций ТН ВЭД

## Требования

- Python >= 3.12
- Доступ к интернету для предварительной загрузке моделей (однократно)

## Инструкция по запуску

### 1. Установка окружения

Установите зависимости (зафиксированы в `requirements.txt`):
   pip install -r requirements.txt


### 2. Предварительная установка моделей выполняется из корня проекта командой:
   python download_models.py
Скрипт загрузит необходимые модели в кеш, после этого модели будут работать локально.

### 3. Опционально. Загрузка собственных входных данных. 
В папке ./data находятся тестовые файлы "declarations.jsonl" и "regulations.jsonl",
опционально замените их на свои файлы с данными. 
Формат и названия файлов должны совпадать с исходными

### 4. Запуск стартового скрипта из корня проекта следующей командой:
   python run.py --data ./data --out ./out 
Дождитесь окончания работы. Выходные данные в виде файла predictions.csv 
находятся папке ./out
### 5. Опционально. Локальная проверка результатов. 
В папке loc_val находятся два вспомогательных скрипта, позволяющие исследовать полученные результаты.
declr_check.py позволяет по номеру декларации увидеть топ 10 релевантных регуляций с описаниями. 
worst_cases.py позволяет вывести топ 10 наиболее плохо объясненных деклараций (с самой маленькой 
оценкой для первого ранга).

## Подход

Решение построено как **гибридный retrieval + reranking пайплайн**:

1. **Гибридный поиск кандидатов** — параллельно работают два метода:
   - **BM25** — лексический поиск по лемматизированным текстам
   - **Dense retrieval** — семантический поиск по эмбеддингам
   
   Результаты объединяются через **Reciprocal Rank Fusion (RRF)**.

2. **Cross-Encoder реранкинг** — топ-20 кандидатов точно оцениваются кросс-энкодером, который выдаёт финальный скор (0–1).

3. **Вывод** — для каждой декларации формируется топ-10 регуляций с рангами и скорами.

## Используемые модели

| Модель | Назначение | Параметры |
|---|---|---|
| `intfloat/multilingual-e5-small` | Эмбеддинги для семантического поиска | ~118M |
| `BAAI/bge-reranker-v2-m3` | Кросс-энкодер для финального реранкинга | ~568M |


Все модели **локальные**, скачиваются один раз при подготовке среды, далее работают офлайн.

## Допущения и ограничения

### 1. Описание регуляций при работе кросс-энкодера обрезается по длине 512 токенов, это сделано, чтобы снизить нагрузку. Кроме того длинный хвост пояснения может внести шумовой компонент и исказить оценку.
### 2. Все вычисления производятся in-memory. Для масштабов тестового датасета использование векторных хранилищ и систем индексации вызовет перерасход ресурсов на запуск без выигрыша в скорости.

## Языковая политика

- **Лемматизация:** русскоязычная (Mystem). Выбрана в условиях ограниченных ресурсов и отсутствия явных требований к мультиязычности. Для поддержки других языков потребуется переход на spaCy/Stanza с соответствующими языковыми пакетами.
- **Эмбеддинги и реранкинг:** мультиязычные модели. Позволяют работать с текстами на разных языках ЕАЭС и корректно обрабатывать латинизированные термины в русскоязычных документах.
## Масштабирование

Если необходимо масштабировать решение - предполагается использовать Elasticsearch (он включает из коробки BM25, dense, RRF; соответственно принцип работы алгоритма не изменится).

## Проблемы и пути решения

Оценка топ 10 наихудших результатов (score 1 ранга минимален среди всех) показала что хуже всего обрабатываются декларации редких товарных групп и/или с обилием узкоспециальных терминов в описании. Базовые модели честно не могут подобрать к таким подходящую регуляцию.
Классические метрики recall@k, precision@k, F1 и производные недоступны, так как нет размеченных данных. 
Метрики покрытия и разнообразия не могут быть применены в полной мере, так как выборка регуляций мала и неизвестен механизм её построения. Выборка регуляций может в принципе не покрывать какие-то декларации.

Пример первых трёх:
1. D0045 ТИЛИДИНА ГИДРОХЛОРИД, CAS 27107-79-7, БЕЛЫЙ КРИСТАЛЛИЧЕСКИЙ ПОРОШОК, ЧИСТОТА 99,5 МАС.% ФАРМАЦЕВТИЧЕСКАЯ СУБСТАНЦИЯ
2. D0116 ОКСИД ЦЕРИЯ CEO2, СВЕТЛО-ЖЕЛТЫЙ ПОРОШОК, ЧИСТОТА 99,9 МАС.% СРЕДНИЙ РАЗМЕР ЧАСТИЦ 1,2 МКМ; ДЛЯ ПОЛИРОВКИ ОПТИЧЕСКОГО СТЕКЛА
3. D0016 БУНКЕР-НАКОПИТЕЛЬ SOLUM B-1200 ДЛЯ СУХИХ ПОЛИМЕРНЫХ ГРАНУЛ, СВАРНОЙ, ИЗ УГЛЕРОДИСТОЙ СТАЛИ, ОБЪЕМ 1200 Л БЕЗ ФУТЕРОВКИ И ТЕПЛОИЗОЛЯЦИИ

Пути улучшения:
1. Использование полного, актуального справочника регуляций. Требует значительных ресурсов для проверки по всей базе сразу.
2. Настройка моделей под специфические таможенные термины с использованием исторических данных.
3. Создание golden set размеченных данных для обучения специализированных на таможенной специфике моделей.
